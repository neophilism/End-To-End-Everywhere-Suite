# Private CLI file boundaries

All CLI imports require bounded regular files. On Unix, selection checks precede a nonblocking open and a second check on the opened descriptor. Pipes and devices are rejected without reading their contents or waiting for a pipe writer. Ordinary explicitly selected file symlinks remain usable; backup recovery additionally rejects final-component symlinks. Reading a file does not execute or render it, and format/authentication checks still follow the file check.

All user-selected CLI exports use the same private publication helper: ciphertext deliveries, public contact exports, plaintext text/attachments and complete encrypted backups. The selected destination must not exist, including a dangling symlink or directory. A final atomic creation check also refuses an entry that appears during preparation.

The helper creates an unpredictable `pending-e2ee-export-*.tmp` file in the controlled destination directory, verifies private permission bits and a single regular-file link, writes and syncs the complete content, and checks cancellation before publishing. A hard link atomically creates the selected destination from the complete inode; it never replaces an existing entry. The pending name is removed and the directory is synced before success. Success leaves a private complete file with one link and no pending name from that operation.

Before publication, cancellation or another preparation error removes the private pending file and syncs that removal. An entry created by another operation at the selected destination is preserved. After publication, cleanup or directory-sync failure reports `OutputCommitUncertain` and keeps the selected complete file; it never tries to compensate by deleting that destination. Inspect its contents/durability and any pending file before retrying. A failed pending cleanup has a distinct uncertainty diagnostic.

For receive-once and backup commands, the encrypted source archive may already have committed before export begins. Their emitted anchor remains authoritative even if export fails. Private file publication does not make receipt commit, independent-anchor storage and external output one atomic transaction; do not interpret an output error as permission to receive or send again automatically. Cancellation after publication cannot undo that publication.

The destination directory and its ancestors must remain controlled by the local user throughout the operation. The implementation needs a local Unix filesystem that supports private permission bits, hard links and directory sync. It fails when those facilities are unavailable; it does not fall back to overwriting or exposing a partial selected file. Native Windows storage and network-filesystem durability guarantees remain unsupported. For other backup media, export first onto a supported private filesystem and handle the external copy and verification explicitly.

A process crash can leave a private pending file before publication. The filename contains random bytes rather than the original filename or plaintext. Removing a pending name is not secure erasure of disk blocks, snapshots or retained copies. Protect the selected directory and any plaintext source/export files as local data outside the encrypted vault.

Real-filesystem tests cover complete private inode visibility before publication, cancellation cleanup, a destination created during preparation, post-publication sync failure with retained complete output, dangling-link refusal, ordinary file-link compatibility, size limits and nonregular inputs. Actual-process text, attachment and backup/restore regressions exercise the shared helper. This is scoped file-integrity evidence; it is not an independent audit, universal filesystem guarantee or certification.
